### API contract (frontend codes against this)

All endpoints are repo-scoped like the existing commands (`/r/{repo}/…` in daemon mode), take `?path=<document>`, and answer errors as `{"error": …}` (409 adds `"reason"`).

| Endpoint                                 | Request                                                                                                                                                                                                               | Answer                                                                                                                  |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `GET /review/evidence`                   | —                                                                                                                                                                                                                     | `{boot_id, document_generation, content_hash, mutation_revision}` (`mutation_revision` is 0 with no review; `no-store`) |
| `POST /review/begin-comment-session`     | `{comment_id, session_id, shown_root_version}`                                                                                                                                                                        | `{session: {session_id, comment_id, state, outcome?, baseline?, root_text_version, stale?, comment?}, review}`          |
| `POST /review/finish-comment-session`    | `{comment_id, session_id}`                                                                                                                                                                                            | same shape; `state: "closed"`, `outcome: "kept"`                                                                        |
| `POST /review/restore-comment-session`   | `{comment_id, session_id}`                                                                                                                                                                                            | same shape; `outcome: "restored"` (existing root) or `"discarded"` (new root, deleted with replies)                     |
| `POST /review/bind-comment-question`     | `{comment_id, question_id, evidence?: {document_generation, document_content_hash, unit_fingerprint, selected_quote}, preconditions: {boot_id, document_generation, mutation_revision, content_hash}, allow_rebind?}` | full review (200)                                                                                                       |
| `POST /review/comments` (extended)       | adds `session_id?`, `question_evidence?`, `preconditions?`                                                                                                                                                            | full review                                                                                                             |
| `PATCH /review/comments/{id}` (extended) | `{comment, session_id?}`                                                                                                                                                                                              | full review                                                                                                             |
| `POST /planning/reviews` (extended)      | unchanged                                                                                                                                                                                                             | each entry gains `evidence: {boot_id, document_generation, content_hash, mutation_revision, sample_changed}`            |

The document is the `path` query parameter and the repository the `/r/{repo}` scope, as for every other command; the body repeats only `comment_id` and `session_id`.

Statuses: session/bind bodies missing ids → 400; unknown session, closed session on a write, deleted root → 404 (no text echoed); `external_text_edit` on restore or on a session write → 409 `{error, reason: "external_text_edit"}`; a refused bind → 409 `reason` is one of `document_unreadable`, `boot_id`, `document_generation`, `content_hash`, `mutation_revision`, `scanner_unavailable`, `question_id` (absent, or not unique in the scan), `unit_fingerprint`, `selected_quote`, `already_bound`. Replay of a closed session on begin/finish/restore is a 200 carrying the stored `outcome`. A begin replay returns the **original** `baseline`.

Review JSON gains: `mutation_revision`, `comment_sessions` (open: `baseline`; closed: id, comment_id, outcome only); comment: `question_evidence`, `root_text_version`, `mutation_counter`, `reply_coverage[{reaction_index, root_text_version?, covers: current|other|unknown}]` (derived on every save; transport for the "reply to discarded wording" / "coverage unknown" labels, not an outcome); reaction: `root_text_version` (echoed by the agent's inbox line as `root_text_version`, never filled in by the server).

### Decisions made while building

- **Conditional capture (repaired in A3).** `recapture` refreshes `captured_block` only on scanner proof, and records the outcome in the comment's `ownership` (`proven`, `unowned`, `unknown`) with `ownership_reason`. A comment **bound to a question** is refreshed when the scanner proves the block at the anchor line lies in that question's unit (its id unique in the scan: `proven`); otherwise the previous capture stays (`unknown`, `question_not_at_anchor`). A comment bound to **no question** (every legacy comment) is a plain note only where the scanner shows the anchor line lies in **no** question unit: then it recaptures per round as ever (`unowned`). Where the anchor lies in a question unit the comment is not bound to — the case of A replaced by B in the same slot — the server holds nothing that says whether that unit is the block the comment captured (no id; words and neighbours are not identity), so the old capture stays (`unknown`, `anchor_in_unbound_question_unit`). With no scanner the capture also stays (`unknown`, `scanner_unavailable`); the comment is preserved and nothing is claimed proven. An unbound comment never triggers a scan on create, only when it is edited or replied to. Consequence: a legacy comment on a question's own text no longer follows that question's in-place edits until it is bound. Restore re-adopts the baseline's capture.
- **Version assignment.** Every text write (create, edit, repeated create with new text) gets a new random `root_text_version` and bumps `mutation_counter`; restore re-adopts the baseline version and bumps the counter. A root that predates this change has no version until its next write, so its replies read _coverage unknown_.
- **Deletion does not close sessions.** A restore or finish after a foreign delete must be a 404 ([§7 step 2](./planning-question-state.md#7-restoring-an-editing-session)), so `DeleteComment` leaves sessions alone; a new-in-session restore records the id in `deleted_ids`.
- **Create with a bare `question_id`.** It is conservative: the id counts only when the scanner proves it names exactly one question and any `question_evidence` (`unit_fingerprint`, `selected_quote`) is about that unit; the stored evidence carries the server-computed fingerprint. Unproven — no scanner installed, scan failed, id absent or duplicated, stale `preconditions` — stores the comment **unbound** (still a 200). The shipped frontend sends a bare id and still works: its comments are unbound, which it already handles as null binding, until the scanner is installed. A retried create never rewrites a held comment's id.
- **Scanner bridge.** The server has no Markdown parser; it runs the checker as `index --format json` in the repository root and reads each question's `id`, `unitLine`, `unitEndLine` and `unitText` (the unit as rendered, emitted by the shared scan from the same tree as `title`). The checker is found at `$VANTAGE_CHECK`, else an executable `vantage-check` beside the running server executable, else `PATH`; none found means nothing is ever bound and ownership is `unknown`/`scanner_unavailable`. Release archives ship both binaries side by side; a server-only install (`go install`, the PyPI `vantage-md` wheel) has no neighbour and needs `vantage-check` on `PATH` or `$VANTAGE_CHECK`. The scanner already assigns an id claimed by separate question runs to no question, and the server also drops any id seen twice. The unit text is those file lines of the document the server hashed, and the unit fingerprint is `ContentHash` of it. Results are cached per (repo, path, content hash), at most 128, scanned lazily and serially (30 s bound); concurrent requests for one generation re-read the cache under the scan lock, so N binds cost one scan (`TestConcurrentReadingsOfOneGenerationScanOnce`), never one per card or comment. A scan counts only if the document's hash after the scan equals the hash before it.
- **Coherent read.** Every command that needs the document reads it (and scans it) after taking the review's lock, so the review revision, the content hash and the units are one reading; a write racing the scan makes the scan unproven rather than stale.
- **Evidence.** The boot id is random per `Store`; the generation is per (repo, path), starts at 1 and increments each time an observed content hash differs from the last observed one (a change never observed is not counted). The hash is the planning scan's content hash (first 128 bits of SHA-256) over the text the server reads.
- **Revision.** `mutation_revision` increments in `saveLocked`, so every persisted change counts; a no-op retry does not save and does not count.

### Limitations (explicit)

- A server without the checker binary never binds a comment to a question (`scanner_unavailable` on bind) and marks recaptures `unknown`; a scan costs a whole-project `index` run per distinct document content, serialized. The scan result covers one document per run; other documents' results are not kept.
- `selected_quote` is compared with the unit's rendered text (`unitText`) after whitespace collapse: a selection across bold, a link or inline code matches, source markup or a link destination does not. A checker too old to report `unitText` falls back to the Markdown source. Containment (exists) is the proof; the quote is not required to occur once.
- A session conflicted by an external edit never recovers on the server; the client opens a new session ("Replace with mine").
- Roots that predate Stage A have no `root_text_version`; their replies read as coverage unknown, and so do all replies of an unversioned root.
- Discarding a new root records the ids of its replies in `deleted_ids`; replies without an id cannot be recorded.

### Decisions

- **The begin and finish reviews are not adopted.** Neither changes text, and a begin ack must not roll back a later save's review; restore's review is adopted (it changed text).
- **Escape/× on an unchanged box finishes**; "unchanged" is no typed difference **and** no write sent in the session (typing back to the original after an autosave still asks).
- **Inline document boxes, the review panel and the popover share one cancel flow.** Escape (and the popover's ×) on a changed session box asks Restore / Discard (naming the reply count for a new root) or Keep editing; Ctrl+Enter and Close finish. React boxes use `useBoxCancel`, the hand-built inline box asks with the same words (`cancelWords`); both restore through `restoreEditingSession`. Reply boxes are not sessions and keep Esc = keep.
- **Ownership cue.** A comment whose `ownership` is `unknown` shows "(ownership unknown)" beside its text on a planning card; no other state is shown and no outcome is claimed. The popover shows the quoted text only and has no cue.
- **Replace with mine** needs the comparison checkbox; it opens a new session on the fresh version, and writes nothing if that begin is stale.

## Stage C1: ownership map, create evidence, unresolved groups

Source-grounded plan, written against the Stage A contract and the planning page.

- **One map** ([questionOwnership.ts](../../frontend/src/lib/questionOwnership.ts)): `ownershipMap(index, byPath)` classifies every held comment against its document's **whole** scan (`document.questions`, `directiveIds`, `ids`; never the listed or filtered subset) as bound / unassigned / ambiguous (id declared more than once) / removed (id in no directive and nowhere in the text) / unknown (document not scanned, or id written in the text outside a directive). It is memoised on the identity of the held scan and the held reviews, so the push-sequence cache that replaces `byPath` is the only recompute and no card rescans.
- **Create evidence** ([useReviewStore.ts](../../frontend/src/stores/useReviewStore.ts)): a create with a `question_id` first reads `GET /review/evidence` and sends `preconditions {boot_id, document_generation, mutation_revision, content_hash}` and `question_evidence {document_generation, document_content_hash, selected_quote}`; the quote is the start of the unit's rendered `unitText` (`questionQuote`). `unit_fingerprint` was left out at C1 (the viewer had no hash of the unit's source lines; the server fills in the one it computes in `proveQuestion`); C1b added the scanner's fingerprint, and creates from a card now send it. If the evidence cannot be read the bare id goes alone and the server stores the comment unbound unless its own scan proves it.
- **Unresolved groups** ([PlanningUnresolved.tsx](../../frontend/src/components/PlanningUnresolved.tsx)): the pending comments Copy answers does not carry, grouped Unassigned / Ambiguous / Removed / Unknown with the original quote, counted separately ("M with unresolved ownership", "Unknown" until every listed document's reviews are read), with their own **Copy unassigned requests**. A comment is in Copy answers or in a group, never both.
- **Lifecycle** (`lifecycleOf`): Open / Response saved, waiting for agent / Agent replied, question still open / Ruling recorded / Unknown, from the scan and the bound comments only.

## Stage C1b: evidence-keyed map, scanner evidence, legacy bind, cues

Written before building (HEAD 90970f49), against the C1 text above and the code:

- **Scanner evidence, one parser.** The shared scanner (`packages/vantage-md/src/planning/scan.ts`, helpers in `evidence.ts`) now emits, per question, `unitFingerprint` — SHA-256 (first 128 bits) of the unit's file lines, each less a trailing CR, joined by `\n`, which is `review.BuildUnit` on the server (a synchronous implementation, because WebCrypto is async and absent on an insecure origin); per document, `ledgerIds` (OQ ids in the first column of tables under a "Decision Ledger" heading) and `blockLines` (anchor hash → file line of the block, `0` where several blocks share the hash). The two fingerprint implementations are pinned to one literal in `internal/review/observation_test.go` and `planningScanEvidence.test.ts`.
- **Map keyed on the reading.** `planning/reviews` entries carry `{boot_id, document_generation, content_hash, mutation_revision, sample_changed}`; `usePlanningReviews` keeps them beside the held comments (never rolling a path back to an older reading of the same boot), a push re-read is now a single-path `POST …/planning/reviews` (a `GET /review` has no evidence), and an own-write echo with no held reading asks for one. `ownershipMap(index, byPath, {evidence, hashes})` reads a path's comments as **Unknown** when evidence is absent, `sample_changed`, or its `content_hash` is not the scan's hash for that path; Copy answers and the counts read only the other paths.
- **Compacted** is a comment on an id in `ledgerIds` and in no directive, drawn as its own group; an id merely written in the text stays Unknown.
- **Legacy auto-bind** (`legacyBindCandidate`, `useLegacyAutoBind`): only an unbound comment whose anchor hash is one block of the whole document (`blockLines[hash] > 0`), lying in exactly one question's unit whose id is unique, and only against a coherent reading. One `bind-comment-question` per (comment, reading), carrying the scanner fingerprint, the quote and the reading as preconditions; a refusal is shown in the server's reason, in plain words, and is not retried until a new reading.
- **Attach to question…** in the unresolved menu for Unassigned / Ambiguous / Removed / Compacted comments: shows the original quote and the chosen question's current text, preselects nothing, binds only on Confirm, with `allow_rebind` when the comment already names a question.
- **Lifecycle** labels on cards (a fixed-width slot); the ownership-unknown cue in the review panel list and the answer popover.

### Not done, and caveats

- `blockLines` hashes the **parsed** text of a block (`textOf`), not the rendered page's `innerText`, so a block whose rendered text differs (math, raw HTML, hidden content) gets a hash the scanner does not hold and is never auto-bound. That fails towards Unassigned, never towards a wrong bind; it is not measured over a real corpus.
- The reported bug "comments on a question the filter hides show as Unassigned" did **not** reproduce at this base for bound comments (`ownership under a filter` in `PlanningPage.test.tsx` is green before any change); the test stays as a regression guard. The real defect found on the way was that a pending comment on a document read against another version stayed in Copy answers; it now reads Unknown.
- The lifecycle label does not yet say "Question removed from document" / "Compacted" on a card (those ids have no card); they are groups.
